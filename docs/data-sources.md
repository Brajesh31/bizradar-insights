# 🧾 Data Sources, Provenance and Limitations

## Purpose

Users should be able to distinguish measured data from estimates, synthetic values, model output and user input. Displaying all values with the same style creates unjustified confidence.

## Provenance taxonomy

| Label | Meaning |
|---|---|
| External/provider | Retrieved from a configured provider API |
| Supabase persisted | Stored user-owned record |
| Local deterministic | Computed from fixed TypeScript formulas |
| Synthetic/randomized | Created from templates/random variation |
| AI-generated | Generated by an external language model |
| User-provided | Entered by the user and not independently verified |

## Source observations

### Market data service
`src/services/marketData.ts` explicitly describes generated market data as mock data. City-tier multipliers and random variation drive demand, competition, density, income and related values. Category opportunity suggestions are drawn from static templates.

### Forecast service
`src/services/forecastEngine.ts` applies constants by category. It should be disclosed as a modeled scenario, not a third-party forecast.

### Local AI helper
`src/services/ai.ts` builds template-based summaries. It is not the same as the LLM gateway calls in Supabase functions.

### Edge Functions
`parse-idea`, `generate-insights`, and `ai-assistant` call the configured Lovable AI Gateway. Generated output can be incomplete, inconsistent or incorrect and must be validated.

### Geocoding/maps
The repository includes geocoding, map rendering and heatmap modules. Confirm provider configuration, coverage, terms, quotas, attribution and freshness before claiming any specific data is live.

### Competitors
Competition scanner and quality analysis may combine provider results with derived/mock attributes. Validate each displayed field's origin before labeling it externally sourced.

## Provenance fields recommended for integration records

- `source_type`
- `source_name`
- `retrieved_at`
- `geographic_precision`
- `coverage_notes`
- `confidence_or_quality`
- `is_synthetic`
- `methodology_version`

## Product wording

Avoid “100% accurate demand”, “verified competitors”, “guaranteed profitability”, or “AI predicts success” without evidence. Prefer “illustrative estimate”, “heuristic score”, “AI-generated summary”, and “estimated coverage”.

## Review checklist
- [ ] Every key metric has a source category.
- [ ] Mock and external data are visually distinguishable.
- [ ] Randomized values are not presented as observations.
- [ ] Freshness is shown where relevant.
- [ ] AI content is labeled.
- [ ] User input is not described as verified.
